# 仓库管理系统 开发文档

> 技术栈：Vue3 + Element Plus + FastAPI (Python) + MySQL
> 部署环境：Ubuntu 24 + 宝塔面板，域名 https://erp.ifungoo.cn/
> 使用规模：3~5 人，无权限区分

---

## 1. 系统概述

一个轻量仓库管理系统，核心围绕 **采购单（入库）** 和 **出库单（生产申领/非工单申领）** 维护物料库存，支持退料、供应商管理、用户管理。

**单据均为"表头 + 明细"结构**：一张采购单可包含多个物料明细；一张出库单可包含多个物料明细；一张退料单对应一张出库单，可退回该单的多个明细行。

**所有单据都有审核流程**：新建后为"待审核"，不参与库存计算；审核通过后才扣减/计入库存。已审核单据不可修改；删除已审核单据会反向回补库存。

### 页面结构

```
登录页
  └─ 主界面（顶部导航 + 左侧子菜单 + 内容区）
      ├─ 库存
      │   ├─ 产品库存（表格；右上：导出库存 / 出库单 / 退料单按钮）
      │   ├─ 出库记录（expand 展开明细 + 状态列 + 审核/删除操作）
      │   └─ 退料记录（expand 展开退回明细 + 退料单按钮）
      ├─ 采购
      │   ├─ 采购管理（表格 expand 展开明细 + 采购人/状态列 + 审核/修改/删除）
      │   └─ 供应商
      ├─ 设置
      │   └─ 用户管理
      └─ 帮助（大白话讲清结构和关系）
```

### 通用 UI 规范

- **分页**：所有表格底部统一分页条（TablePager 组件）：左侧显示"共 X 条"，右侧"上一页/页码/下一页 + 每页条数"（25/50/100/200，默认 25），客户端分页
- **搜索**：所有表格顶部中间为联想下拉搜索框（el-select remote）：输入关键字 → 下拉列出匹配记录 → 每行按该页面表格的列形式展示（如出库记录显示"日期|单号|领料人|备注"）→ 点击选中即按该关键字过滤表格；清空恢复全量
- **弹窗打印按钮**：所有弹窗打印按钮统一在左下角（footer 左右布局）

## 3. 核心业务规则

### 3.1 当前实际库存数量

> 某物料的实际库存 = 该物料所有 **已审核采购明细行** 的 `remaining_qty` 之和
> 其中：`remaining_qty = purchase_qty - claimed_qty + return_qty`
> 待审核采购单的明细行不参与任何库存计算。

### 3.2 采购单与供应商

- 一张采购单只对应 **一个供应商**，单内明细可含 **多个物料/物料编号**
- 需要从多个供应商采购时，**分多张采购单** 开出
- 采购单含 **采购人** 字段
- **审核流程**：新建为待审核（CG 单号已生成但不占库存）→ 审核通过才计入库存；**仅待审核可修改**（复用添加弹窗与接口，明细全删全建）；已审核不可修改

### 3.3 出库单与审核流程

出库单分两类申领：

| 申领类型 | 单号前缀 | 说明 |
|---|---|---|
| 生产申领 | CK_ | 默认类型，工单领料 |
| 非工单申领 | FQ_ | 非工单的零星领料；备注为空时自动写"非工单申领" |

**审核流程（与采购单一致的 pending → approved 模式）：**

1. **创建**：只登记表头和明细，`status = pending`，**不做任何 FIFO 扣减**，库存不变
2. **审核通过**（POST `/issues/{id}/approve`）：此刻才执行 FIFO 扣减，然后置 `approved`
3. **待审核单不能退料**（接口返回 400"出库单尚未审核"）
4. **删除规则**：
   - 待审核单：直接删（没扣过库存）
   - 已审核单：若有退料记录 → 拒绝删除，提示"请先删除对应退料单"；否则按 LIFO（从新到老）反向回补采购行 `claimed_qty`，再删单
5. 历史导入数据无 status，代码层默认视为 `approved`（不改变行为）

### 3.4 申领（出库）FIFO 扣减规则（审核时执行）

出库单明细行申领 N 个物料 X（仅针对 **已审核采购单**）：

1. 找到该物料 **入库日期最老** 的采购明细行
2. 从其 `claimed_qty` 中扣除（即 remaining 减少）
3. 该行剩余不够 → 差额继续往下一笔（更新入库日期）采购明细行扣
4. **扣到负数为允许**：最后一笔（最新日期）采购明细行 `claimed_qty` 扣成负数，即 remaining 为负，表示"欠账"
5. 没有任何已审核采购行 → 审核报错"没有已审核的采购单"

### 3.5 新建/审核采购明细的负数结转规则

采购单 **审核通过瞬间**（非创建时），对新明细行按物料执行：

1. 查该物料上一笔采购明细行
2. 若上一笔 `remaining < 0`（被扣穿成欠账）：
   - 取负数绝对值，设为新明细行的初始 `claimed_qty`（预扣）
   - 上一笔明细行 remaining 归零
3. 之后新申领从新明细行正常扣除

> 通俗理解：上一笔被扣穿成负数的明细行，用新采购明细行"还账归零"，欠账转移到新明细行上继续扣。

### 3.6 退料单规则

1. 退料单 **只能针对一张出库单，且该出库单必须已审核**：弹窗中只能搜索出库单（按单号/领料人/物料名称编号模糊搜）
2. 选定出库单后，**列出该出库单全部明细**
3. 出库单的 **出库数量锁定不可改**，仅可修改 **回退数量**（上限 = qty - 已退回量）
4. **重新选择出库单 → 之前所有修改作废**（重新拉取明细覆盖），一次只对一张出库单做退料
5. 提交后：写 `return_orders` + `return_items`，累计 `issue_items.return_qty`
6. 同时按 **LIFO 反向**（从最新入库明细优先）回补采购明细行的 `return_qty`（仅已审核采购行，回补量 = 该行被占用量 occupied = claimed - return）

### 3.7 工单号规则

- 格式：`PREFIX_YYYYMMDDNNN`，如 `CK_20260828001`，NNN 当日从 001 递增
- 前缀：**CG** 采购 / **CK** 生产出库 / **FQ** 非工单出库 / **TL** 退料
- 用 order_seq 表 + 事务保证并发不重号
- 历史导入数据中 FQ 单号可能为 8 位日期（如 FQ_20260901001 之后出现 FQ_20260901002 形式的虚拟合并单），是台账导入时按日期合并非工单申领行生成的虚拟单号，属预期

## 4. API 设计（FastAPI）

统一前缀 `/api`，JWT 登录鉴权（登录为 `/login`，无 /api 前缀）。

### 认证
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /login | 登录，返回 token |
| GET | /auth/me | 当前用户 |

### 用户管理
| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | /api/users | 列表 / 新增 |
| PUT/DELETE | /api/users/{id} | 修改 / 删除 |

### 物料
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/materials?keyword= | 搜索（编号/名称模糊）——弹窗下拉远程搜索用 |
| POST | /api/materials | 新增物料 |

### 库存
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/inventory?keyword= | 产品库存表（按物料聚合，**仅统计已审核采购单**：实际库存/采购总数/申领总数/退回总数/规格/备注） |
| GET | /api/inventory/export | 导出当前库存 Excel |

### 采购
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/purchases?keyword= | 采购单列表（含 items 明细，keyword 匹配单号/供应商/物料） |
| POST | /api/purchases | 新建采购单（pending，不占库存）：supplier_id + purchaser + purchase_date + in_stock_date + items[] |
| PUT | /api/purchases/{id} | **修改采购单（仅待审核可改）**：入参结构与新建相同，明细全删全建 |
| POST | /api/purchases/{id}/approve | **审核采购单**：通过后计入库存，并对新明细行做负数结转 |
| GET | /api/purchases/by-material/{material_id} | 物料采购明细（剩余≠0 的行，库存详情弹窗用） |

### 出库（申领）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/issues?keyword= | 出库单列表（含 items、issue_type、status；keyword 匹配单号/领料人/物料） |
| POST | /api/issues | 创建出库单（**pending，不扣库存**）：issuer + issue_type（生产申领/非工单申领）+ issue_date + remark + items[{material_id, qty, remark}] |
| POST | /api/issues/{id}/approve | **审核出库单**：通过后执行 FIFO 扣减 |
| DELETE | /api/issues/{id} | **删除出库单**：待审核直接删；已审核反向回补库存（有退料记录的拒绝） |
| GET | /api/issues/{order_no}/detail-for-return | 退料弹窗：返回该出库单全部明细（含 qty/returned/returnable） |

### 退料
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/returns?keyword= | 退料单列表（含 items 明细、对应出库单号） |
| POST | /api/returns | 创建退料单（要求出库单已审核）：issue_order_no + return_date + remark + items[{issue_item_id, qty}]，LIFO 回补 |

### 供应商
| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | /api/suppliers | 列表 / 新增 |
| PUT/DELETE | /api/suppliers/{id} | 修改 / 删除 |

### 关键交互

- **审核/删除**（采购、出库同模式）：审核前弹确认框（"审核后立即扣减/计入库存"）；删除前弹确认框（已审核单提示会回补库存）。状态用 el-tag 展示（已审核绿 / 待审核橙）
- **修改采购单**：仅待审核显示"修改"按钮，打开与添加相同的弹窗，预填表头和明细，提交走 PUT 接口
- **联想搜索框**：所有列表页顶部搜索为 el-select remote，输入即请求后端 keyword 接口，下拉选项按页面列形式排版（opt-row 样式），选中即过滤；清空恢复全量
- **出库弹窗**：明细行物料远程搜索（el-select remote），选中自动带出编号/规格/当前库存；提交后提示"出库单已保存待审核，单号 XXX"
- **退料弹窗**：只能搜索出库单（选项显示单号+日期+领料人）；选定后调 `/issues/{no}/detail-for-return` 列明细；回退数量 `:max="row.returnable"`；重新选择出库单即覆盖作废
- **采购弹窗**：采购人/采购日期/入库日期一行 + 备注一行 + 明细小表格（添加明细/删除行），物料选中自动填充编号规格
- **弹窗 footer**：打印按钮靠左（footer-left），确定/取消靠右（全局 CSS `.el-dialog__footer` 布局）

## 7. 部署方案（宝塔 + Ubuntu 24）

### 7.1 后端
1. 宝塔 **Python 项目管理器** 创建项目，目录 `/www/wwwroot/ifungoo_erp`
2. 虚拟环境 `venv/`，依赖 requirements.txt
3. 启动命令：`venv/bin/uvicorn main:app --host 127.0.0.1 --port 39800`
4. 端口固定 **39800**

### 7.2 前端与 Nginx（纯反代架构）
1. 本地 `npm run build` 产出 dist/，上传到 `/www/wwwroot/ifungoo_erp/frontend/dist`
2. **FastAPI 直接托管前端**（app/main.py：mount /assets + catch-all 返回 index.html）
3. Nginx **不做静态分流、不加 location /api**，全部请求反代到 127.0.0.1:39800：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name erp.ifungoo.cn;
    location / {
        proxy_pass http://127.0.0.1:39800;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> 这样宝塔后续重写 nginx 配置（如申请 SSL）也不会破坏页面路由，只维护一条反代规则。

### 7.3 数据库
- 库名 `ifungoo_erp`，账号 ifungoo
- 建表由 SQLAlchemy `create_all` 自动完成（首启动）
- **已有表的加列变更**：create_all 不会改已有表，需写迁移脚本（参考 _migrate.py 方式，用 SQLAlchemy `ALTER TABLE` 执行），或 DROP 表重建（会丢数据，慎用）
- 已执行过的迁移：purchase_orders 加 purchaser/status；issue_orders 加 issue_type/status；return_orders 加 remark；materials 加 remark

### 7.4 HTTPS
- 宝塔 SSL，Let's Encrypt 免费证书（nginx 需监听 IPv6 80 端口供 http-01 验证）

### 7.5 一键同步部署（deploy.ps1）

> 本地与服务器路径映射已固化，改完代码一条命令同步，无需手动 pscp 逐文件传。

```powershell
.\deploy.ps1              # 后端 + 前端全部同步（前端自动 npm run build）
.\deploy.ps1 -Backend     # 只同步后端 app/ + main.py
.\deploy.ps1 -Frontend    # 只构建并上传前端
.\deploy.ps1 -File app\routers\issues.py   # 只传单个文件
```

- 连接方式：plink/pscp，主机 `root@[2409:8a55:9435:d140:aab8:e0ff:fe08:2431]`（IPv6）
- 原理：tar 打包 → pscp 上传 → 服务器解压覆盖；后端自动清 __pycache__，前端先备份旧 dist 再替换
- **注意：后端代码同步后需去宝塔重启 Python 项目才生效；前端强刷（Ctrl+F5）即可**

- **审核模式统一**：采购单、出库单均为 pending → approved；pending 不参与库存计算；approve 时才执行扣减/结转；历史数据默认 approved
